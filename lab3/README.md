# Лабораторная работа №3 по ООП — вариант 6

**Тема:** «Изучение базовых приёмов ООП: наследование и полиморфизм».

**Цель:** закрепить public-наследование, динамический полиморфизм, виртуальные функции, перегрузку операторов, правило пяти и ручное управление динамическим массивом объектов.

**Вариант:** правильные выпуклые пятиугольник (`Pentagon`), шестиугольник (`Hexagon`) и восьмиугольник (`Octagon`).

## Задание

Разработать иерархию фигур с общим абстрактным базовым классом `Figure`, хранением всех вершин, вычислением центра и площади, потоковым вводом/выводом, клонированием и полиморфным сравнением. Реализовать владеющий динамический массив `Figure*` с автоматическим расширением, глубоким копированием и удалением элементов. Добавить консольный командный интерфейс и автоматические тесты.

## Сборка

Команды ниже выполняются из корня проекта. Для проверенной конфигурации Windows + MinGW:

```bash
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel
```

Если настроен другой компилятор и генератор, параметр `-G` можно изменить или опустить.

Создаются библиотека `figures`, демонстрационная программа `lab3_demo` и тестовая программа `lab3_tests`. На Windows исполняемые файлы имеют имена `lab3_demo.exe` и `lab3_tests.exe`.

## Формат команд

- `add 5` — после команды ввести 5 пар координат `x y` и добавить пятиугольник;
- `add 6` — ввести 6 пар и добавить шестиугольник;
- `add 8` — ввести 8 пар и добавить восьмиугольник;
- `list` — вывести тип, вершины, геометрический центр и площадь каждой фигуры;
- `total` — вывести суммарную площадь;
- `remove N` — удалить фигуру с нулевым индексом `N`;
- `exit` — завершить работу.

Координаты — вещественные числа, разделённые пробелами или переводами строк. Вершины задаются последовательно по или против часовой стрелки. Допускаются только невырожденные правильные выпуклые многоугольники выбранного типа. Проверяются конечность координат, ненулевые стороны, одинаковая длина сторон, равенство углов и выпуклость. При ошибке ввода или проверки фигура не добавляется.

## Ход выполнения работы

1. **Анализ задания.** Выделены два уровня владения данными: каждая фигура хранит фиксированный набор вершин, а массив владеет динамически созданными объектами разных производных типов. Определены требования к проверке правильности многоугольника и безопасному копированию.
2. **Проектирование `Figure`.** Создан абстрактный класс с виртуальным деструктором и операциями `center`, `read`, `print`, преобразования в `double`, `clone`, `equals` и получения имени типа. Нечленные операторы потоков делегируют работу виртуальным методам.
3. **Реализация фигур.** `Pentagon`, `Hexagon` и `Octagon` публично наследуют `Figure` и хранят соответственно `std::array` из 5, 6 и 8 объектов `Point`. Конструкторы и потоковый ввод проверяют геометрические ограничения.
4. **Полиморфные операции.** Площадь вычисляется по формуле шнурования, центр — как среднее координат. `clone` создаёт объект фактического производного типа. Сравнение через `Figure` учитывает динамический тип и использует допуск при сравнении координат.
5. **Массив `Figure*`.** Реализован самостоятельный `FigureArray` на динамическом массиве указателей. При заполнении ёмкость увеличивается вдвое. Массив владеет объектами, удаляет их в деструкторе и при удалении по индексу, проверяет границы и вычисляет общую площадь.
6. **Глубокое копирование и перемещение.** Конструктор копирования вызывает `clone` для каждого элемента. Копирующее присваивание использует идиому copy-and-swap. Перемещение передаёт указатель на буфер и обнуляет источник, исключая двойное освобождение.
7. **Удаление.** `remove` сначала проверяет индекс, уничтожает выбранный объект, сдвигает указатели влево и очищает последнюю ячейку. После перемещения массив остаётся пригодным для повторного использования.
8. **Командный интерфейс.** В `main.cpp` реализован только разбор команд и вывод результатов. До добавления объект размещается под `unique_ptr`; владение передаётся массиву только после успешного ввода. Ошибки координат, геометрии, команд и индексов обрабатываются без аварийного завершения.
9. **Тестирование.** GoogleTest подключён через CMake. Тесты разделены на проверки фигур и массива. Дополнительно выполнен демонстрационный запуск с заранее подготовленным входным потоком.

**Вывод:** наследование и виртуальные функции позволили работать с разными фигурами через единый интерфейс. Явное владение, `clone` и правило пяти обеспечили безопасное копирование и освобождение памяти без поверхностного копирования указателей.

## Результаты тестирования

Проект настроен и собран в конфигурации Debug с помощью CMake 4.4.4, генератора MinGW Makefiles и GCC 14.2.0. Команда `ctest --test-dir build --output-on-failure` выполнена фактически:

```text
100% tests passed, 0 tests failed out of 21
Total Test time (real) = 0.18 sec
```

Пройдены проверки центра и площади всех фигур, переноса, потоков, преобразования в `double`, копирования, перемещения, равенства, полиморфизма, клонирования, глубокого копирования и независимости копий, расширения и удаления в массиве, суммарной площади и неверных индексов. Отдельно проверены отклонение вырожденных, невыпуклых, неправильных и нечисловых данных.

Демонстрационная программа также запущена с приведённым выше вводом и завершилась с кодом 0.

## Размещение на GitHub

1. Создать новый пустой репозиторий на GitHub без автоматически созданных файлов.
2. В корне проекта выполнить `git init`, `git add .` и проверить состав через `git status`.
3. Убедиться, что каталог `build/` исключён, а исходники, тесты, README и `docs/theory.pdf` включены.
4. Создать commit, добавить удалённый репозиторий `git remote add origin <URL>` и отправить ветку командой `git push -u origin main`.

Каталог `build/` не предназначен для публикации: его можно восстановить командами CMake.
