# Лабораторная работа №3 по ООП

## Изучение базовых приёмов ООП: наследование и полиморфизм

**Вариант 6:** правильные выпуклые пятиугольник, шестиугольник и восьмиугольник.

**Цель работы:** изучить и применить наследование, динамический полиморфизм, виртуальные функции, перегрузку операторов, полиморфное копирование и правило пяти при разработке иерархии геометрических фигур и массива указателей на базовый класс.

## 1. Public-наследование

Наследование позволяет создать новый класс на основе существующего. При public-наследовании открытые члены базового класса остаются открытыми в производном классе, а защищённые остаются защищёнными. Главное смысловое свойство public-наследования — отношение «является»: `Pentagon` является `Figure`, поэтому объект `Pentagon` можно использовать через указатель или ссылку на `Figure`.

```cpp
class Figure {
public:
    virtual ~Figure() = default;
    virtual Point center() const = 0;
};

class Pentagon final : public Figure {
public:
    Point center() const override;
};
```

Закрытые данные базового класса остаются недоступны производному классу напрямую. В данном проекте базовый класс задаёт только интерфейс, а координаты хранятся в каждом производном классе. Это позволяет использовать `std::array<Point, 5>`, `std::array<Point, 6>` и `std::array<Point, 8>` без динамического выделения памяти под вершины.

Ключ `final` запрещает дальнейшее наследование от конкретных фигур. Оно не является обязательным для полиморфизма, но явно фиксирует проектное решение.

## 2. Статический и динамический полиморфизм

Полиморфизм позволяет использовать единую запись для работы с разными типами.

**Статический полиморфизм** разрешается во время компиляции. К нему относятся перегрузка функций, перегрузка операторов и шаблоны. Например, компилятор выбирает реализацию `operator<<` по типам аргументов.

**Динамический полиморфизм** выбирает вызываемую функцию во время выполнения по фактическому типу объекта. Для этого используются виртуальные функции и доступ через указатель или ссылку на базовый класс.

```cpp
Pentagon pentagon(vertices);
Hexagon hexagon(otherVertices);

Figure* figure = &pentagon;
Point first = figure->center();  // Pentagon::center

figure = &hexagon;
Point second = figure->center(); // Hexagon::center
```

Если метод не виртуальный, вызов через `Figure*` был бы привязан к статическому типу `Figure`. В проекте виртуальными являются все операции, поведение которых зависит от фактического многоугольника.

## 3. Виртуальные функции, override и виртуальный деструктор

Чисто виртуальная функция содержит `= 0` и делает класс абстрактным. Нельзя создать самостоятельный объект `Figure`, но можно объявлять `Figure*` и `Figure&`. Производный класс становится конкретным только после реализации всего чисто виртуального интерфейса.

Спецификатор `override` просит компилятор проверить, что метод действительно переопределяет виртуальную функцию базового класса с тем же типом. Он помогает обнаружить ошибки в имени, параметрах, квалификаторе `const` и других несоответствиях сигнатуры.

```cpp
class Figure {
public:
    virtual ~Figure() = default;
    virtual operator double() const = 0;
    virtual Figure* clone() const = 0;
};

class Hexagon final : public Figure {
public:
    operator double() const override;
    Figure* clone() const override;
};
```

Виртуальный деструктор необходим при удалении производного объекта через указатель на базовый класс:

```cpp
Figure* figure = new Octagon(vertices);
delete figure; // Корректно: деструктор Figure виртуальный.
```

Без виртуального деструктора такое удаление имело бы неопределённое поведение. В `FigureArray` объекты удаляются именно через `Figure*`, поэтому виртуальный деструктор является обязательной частью проекта.

## 4. Вызовы через Figure* и объектный slicing

Указатель `Figure*` может ссылаться на `Pentagon`, `Hexagon` или `Octagon`. При вызове виртуальной функции используется динамический тип объекта. Это позволяет хранить разные фигуры в одном массиве и обрабатывать их единообразно:

```cpp
for (std::size_t i = 0; i < figures.size(); ++i) {
    Figure* figure = figures.at(i);
    std::cout << figure->typeName() << '\n';
    std::cout << static_cast<double>(*figure) << '\n';
}
```

**Объектный slicing** (срезка) возникает при копировании производного объекта по значению в объект базового класса. Производная часть теряется. Для абстрактного `Figure` прямое создание срезанного объекта невозможно, но общая проблема сохраняется для полиморфных иерархий: объекты следует хранить через указатели или ссылки, а не копировать в базовый тип по значению.

Срезку не следует путать с копированием указателя. Присваивание одного `Figure*` другому копирует только адрес; объект остаётся прежним и принадлежность ресурса должна быть определена отдельно.

## 5. Перегрузка операторов

### operator<< и operator>>

Нечленные операторы получают поток и объект `Figure`. Они вызывают виртуальные методы `print` и `read`, поэтому сохраняется динамическое поведение:

```cpp
std::ostream& operator<<(std::ostream& output,
                         const Figure& figure) {
    figure.print(output);
    return output;
}

std::istream& operator>>(std::istream& input, Figure& figure) {
    figure.read(input);
    return input;
}
```

Возврат потока позволяет объединять операции в цепочку и проверять состояние потока. В проекте ввод выполняется сначала во временный массив вершин. Только после полного чтения и успешной проверки геометрии новые координаты заменяют старые. Так обеспечивается строгая для этой операции гарантия: ошибка не оставляет объект частично изменённым.

### operator==

Каждый производный класс поддерживает сравнение с объектом своего типа. Полиморфное сравнение через базовый интерфейс дополнительно проверяет динамический тип с помощью `dynamic_cast`:

```cpp
bool Pentagon::equals(const Figure& other) const {
    const auto* value = dynamic_cast<const Pentagon*>(&other);
    return value != nullptr && *this == *value;
}
```

Пятиугольник не считается равным шестиугольнику даже при совпадении площади. Координаты сравниваются с абсолютно-относительным допуском, поскольку `double` представляет многие десятичные значения приближённо.

### Приведение к double

Оператор преобразования используется для получения площади:

```cpp
const Figure& figure = octagon;
double area = static_cast<double>(figure);
```

Оператор виртуальный, поэтому вызывается реализация фактического типа. Явный `static_cast` делает назначение преобразования понятным и не создаёт неявных неожиданных преобразований в арифметических выражениях.

## 6. Копирование, перемещение и Rule of Five

Пять специальных операций образуют **Rule of Five**:

1. деструктор;
2. конструктор копирования;
3. копирующее присваивание;
4. конструктор перемещения;
5. перемещающее присваивание.

Если класс вручную управляет ресурсом, обычно требуется осмысленно определить все пять операций. Иначе автоматически созданные операции могут поверхностно скопировать указатель или нарушить владение.

Для фигур ресурсом является только встроенный `std::array` координат. Поэтому специальные операции объявлены как `default`: компилятор корректно копирует или перемещает все элементы. После перемещения `double` остаются в исходном объекте, но это допустимо: сам массив значений не владеет внешним ресурсом.

Для `FigureArray` правило пяти реализовано вручную, поскольку класс владеет динамическим буфером и объектами по указателям.

Перемещение массива передаёт адрес буфера и обнуляет источник:

```cpp
FigureArray::FigureArray(FigureArray&& other) noexcept
    : figures_(std::exchange(other.figures_, nullptr)),
      size_(std::exchange(other.size_, 0)),
      capacity_(std::exchange(other.capacity_, 0)) {}
```

После этого деструктор источника не удаляет переданные объекты. Источник находится в корректном пустом состоянии и может использоваться повторно. Спецификатор `noexcept` важен для операций, которые только переставляют указатели и не выделяют память.

## 7. Глубокое и поверхностное копирование

При **поверхностном копировании** копируются значения указателей. Два массива начинают ссылаться на одни и те же объекты. Изменение через одну копию видно через другую, а деструкторы могут выполнить двойной `delete`.

При **глубоком копировании** создаются новые независимые объекты. В проекте конструктор копирования `FigureArray` выделяет собственный буфер и для каждого элемента вызывает `clone`:

```cpp
for (std::size_t i = 0; i < size_; ++i) {
    figures_[i] = other.figures_[i]->clone();
}
```

Копирующее присваивание использует идиому copy-and-swap: сначала создаётся полноценная копия, затем обмениваются внутренние состояния. Временный объект удаляет старое содержимое. Такой порядок также обеспечивает безопасность при исключении во время копирования.

Тесты проверяют не только равенство значений, но и различие адресов объектов, возможность удалить элемент из копии без изменения оригинала и независимое изменение координат.

## 8. Назначение clone

Обычный конструктор копирования требует знания конкретного типа во время компиляции. Если имеется только `Figure*`, нельзя правильно создать копию выражением `new Figure(*figure)`: базовый класс абстрактен, а копирование в базовый тип привело бы к срезке.

Виртуальный `clone` решает задачу полиморфного копирования:

```cpp
Figure* Pentagon::clone() const {
    return new Pentagon(*this);
}
```

Вызов через базовый указатель выбирает производную реализацию и возвращает объект фактического типа. Владение возвращённым указателем получает `FigureArray`. Метод используется только там, где нужна независимая копия, а не при автоматическом расширении буфера: при росте массива достаточно перенести существующие указатели.

## 9. Центр и площадь многоугольника

Геометрический центр в рамках задания вычисляется как среднее арифметическое координат всех вершин:

```text
cx = (x1 + x2 + ... + xn) / n
cy = (y1 + y2 + ... + yn) / n
```

Это центр вершин, а не общий центр масс произвольного неоднородного многоугольника. Для правильного многоугольника он совпадает с центром описанной окружности.

Площадь вычисляется по координатам с помощью формулы шнурования (shoelace formula):

```text
2S = |sum(xi * y(i+1) - x(i+1) * yi)|
```

Индексы рассматриваются по модулю `n`, поэтому последняя вершина соединяется с первой. Абсолютное значение делает результат независимым от направления обхода.

```cpp
double polygonArea(const Point* points, std::size_t count) {
    double sum = 0.0;
    for (std::size_t i = 0; i < count; ++i) {
        const Point& a = points[i];
        const Point& b = points[(i + 1) % count];
        sum += a.x * b.y - b.x * a.y;
    }
    return std::abs(sum) / 2.0;
}
```

Для контроля результатов тесты сравнивают площадь с формулой правильного многоугольника: `S = n R^2 sin(2 pi / n) / 2`, где `R` — радиус описанной окружности. Перенос всех вершин на один вектор меняет центр, но не должен менять площадь.

## 10. Проверка правильной выпуклой фигуры

Конструктор с вершинами и потоковый ввод применяют одинаковую проверку:

- число вершин фиксируется типом;
- координаты должны быть конечными числами;
- каждая сторона должна иметь ненулевую длину;
- квадраты длин всех сторон должны совпадать в пределах допуска;
- направления векторных произведений соседних сторон должны быть одинаковыми, что обеспечивает выпуклость и согласованный порядок обхода;
- косинусы внутренних углов должны совпадать в пределах допуска.

Проверки равенства сторон и углов нужны совместно: выпуклый равносторонний многоугольник с числом сторон больше четырёх не обязательно правильный. Ввод принимается как по часовой стрелке, так и против неё. Вырожденные и невыпуклые наборы отклоняются исключением `std::invalid_argument`, а командный интерфейс не добавляет такую фигуру.

## 11. Управление памятью в массиве Figure*

`FigureArray` хранит динамически выделенный массив `Figure**`, текущий размер и ёмкость. Класс следует явному правилу владения: после успешного `add` объект принадлежит массиву.

При нехватке ёмкости выделяется новый буфер, обычно вдвое больший. В него копируются только указатели, старый буфер освобождается через `delete[]`, а сами фигуры не копируются и не удаляются. Амортизированная стоимость добавления остаётся постоянной.

Удаление элемента по индексу выполняется так:

1. проверить `index < size`;
2. удалить объект через виртуальный деструктор;
3. сдвинуть последующие указатели на одну позицию;
4. уменьшить размер и записать `nullptr` в освободившуюся ячейку.

Деструктор массива удаляет каждый объект, затем буфер и обнуляет состояние. При перемещающем присваивании старое содержимое сначала освобождается, после чего принимается буфер источника. Проверка самоприсваивания предотвращает потерю ресурса.

В командном интерфейсе до передачи массиву используется `std::unique_ptr<Figure>`. Если чтение или проверка завершилось ошибкой, `unique_ptr` сам удаляет объект. Вызов `release` выполняется только после успешного добавления. Это исключает утечку на промежуточных ошибках.

## 12. Применение теории в проекте

Проект объединяет рассмотренные механизмы в одной модели:

- `Figure` определяет общий абстрактный контракт;
- `Pentagon`, `Hexagon` и `Octagon` реализуют его через public-наследование;
- `center`, `read`, `print`, `operator double`, `clone` и `equals` демонстрируют динамический полиморфизм;
- нечленные потоковые операторы делегируют виртуальным методам;
- `FigureArray` единообразно хранит разные типы через `Figure*`;
- `clone` исключает срезку и поверхностное копирование;
- Rule of Five определяет владение буфером и объектами;
- геометрические функции работают с координатами и не зависят от конкретного числа вершин;
- тесты вызывают операции как напрямую, так и полиморфно через базовый указатель.

Разделение заголовков и реализации уменьшает связность. `main.cpp` отвечает только за команды, а геометрия и управление памятью находятся в отдельных файлах библиотеки.

## 13. Вероятные контрольные вопросы и краткие ответы

**1. Чем public-наследование отличается от private и protected?**  
При public-наследовании сохраняется отношение «является» и преобразование производного типа к открытому базовому доступно вне класса. При private и protected такое внешнее преобразование недоступно, а область видимости унаследованных членов ограничивается.

**2. Зачем нужен виртуальный деструктор?**  
Чтобы `delete` через базовый указатель вызывал деструктор фактического производного объекта и корректно освобождал его ресурсы.

**3. Что проверяет override?**  
Что функция имеет подходящую сигнатуру и действительно переопределяет виртуальную функцию базового класса.

**4. Можно ли создать объект Figure?**  
Нет, класс абстрактен из-за чисто виртуальных функций. Можно создавать указатели и ссылки на него.

**5. Когда выбор виртуальной функции происходит во время выполнения?**  
При вызове через указатель или ссылку на базовый класс выбирается реализация динамического типа объекта.

**6. Что такое slicing?**  
Потеря производной части объекта при копировании по значению в базовый тип. Хранение через указатели и использование `clone` предотвращают эту проблему.

**7. Почему недостаточно скопировать массив указателей?**  
Обе копии будут владеть одними объектами, возникнут зависимость копий и риск двойного удаления. Нужно клонировать каждый объект.

**8. Почему clone виртуальный?**  
Чтобы копирование через `Figure*` создавало объект фактического производного типа.

**9. Что описывает Rule of Five?**  
Необходимость согласованно определить деструктор, две копирующие и две перемещающие операции для класса, вручную управляющего ресурсом.

**10. Чем перемещение отличается от копирования?**  
Перемещение передаёт владение ресурсом без создания независимой копии. Источник оставляют в корректном состоянии, обычно пустым.

**11. Зачем возвращать поток из operator>> и operator<<?**  
Для цепочек операций и стандартной проверки состояния потока.

**12. Почему сравнение double выполняется с допуском?**  
Из-за конечной точности представления и округлений математически близкие вычисления могут дать немного разные значения.

**13. Как вычисляется центр в этой работе?**  
Как среднее арифметическое координат всех вершин по каждой оси.

**14. Зависит ли площадь по формуле шнурования от направления обхода?**  
Знак промежуточной суммы зависит, но итоговая площадь нет, поскольку берётся модуль.

**15. Почему при росте FigureArray не вызывается clone?**  
Массив продолжает владеть теми же объектами; меняется только буфер указателей. Клонирование потребовалось бы лишнюю работу и изменило бы адреса объектов.

**16. Как предотвращается добавление неверной фигуры?**  
Координаты проверяются до передачи владения массиву. При ошибке конструктор или ввод выбрасывает исключение, а временный владелец освобождает память.

## Заключение

В работе реализована полиморфная иерархия правильных многоугольников и собственный владеющий массив указателей на базовый класс. Public-наследование обеспечило единый интерфейс, виртуальные функции — выбор поведения по динамическому типу, а `clone` — независимое копирование без срезки. Правило пяти, виртуальный деструктор и явная передача владения предотвращают утечки и двойное удаление. Вычисления центра и площади, обработка ошибочных данных и автоматические тесты подтверждают практическое применение изученных механизмов ООП.
