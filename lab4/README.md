# Лабораторная работа №4 по ООП

## Основы метапрограммирования

**Вариант 7:** правильный шестиугольник, правильный восьмиугольник и равносторонний треугольник.

**Цель работы:** изучить шаблоны классов, ограничения concepts, безопасное владение ресурсами через умные указатели, глубокое копирование и семантику перемещения, а также реализовать собственный динамический массив без `std::vector`.

## Задание

Проект реализует:

- собственный `concept Scalar`, основанный на `std::is_scalar_v`;
- `Point<T>`, абстрактный `Figure<T>` и фигуры `Hexagon<T>`, `Octagon<T>`, `Triangle<T>`;
- хранение вершин в `std::array<std::unique_ptr<Point<T>>, N>`;
- вычисление центра и площади, потоковый ввод/вывод, глубокое копирование, перемещение, сравнение и виртуальный `clone`;
- проверку невырожденности, строгой выпуклости и правильности введённой фигуры;
- собственный `Array<T>` на `std::shared_ptr<T[]>` с расширением через `std::move`;
- полиморфный массив `Array<std::shared_ptr<Figure<double>>>` для интерактивной программы;
- отдельные демонстрации `Array<std::shared_ptr<Figure<int>>>` и `Array<Hexagon<int>>`;
- автоматические тесты GoogleTest и интеграцию с CTest.

Сырые указатели для владения и хранения объектов не применяются. Пример `Array<Figure<int>*>` из методички намеренно заменён на `Array<std::shared_ptr<Figure<int>>>`, поскольку прямой запрет сырых указателей в задании имеет приоритет.

## Формат ввода

```text
add 6     добавить правильный шестиугольник
add 8     добавить правильный восьмиугольник
add 3     добавить равносторонний треугольник
list      вывести тип, вершины, центр и площадь каждой фигуры
total     вычислить общую площадь
remove N  удалить фигуру с нулевым индексом N
exit      завершить программу
```

После `add` вводится соответствующее число пар `x y`. Вершины задаются последовательно по или против часовой стрелки. Программа отклоняет нечисловой ввод, вырожденные и невыпуклые наборы, а также координаты, не образующие выбранную правильную фигуру. После ошибочного `add` объект не добавляется.

Невырожденные правильные треугольник, шестиугольник и восьмиугольник не могут иметь одновременно только целочисленные координаты. Поэтому демонстрация `T=int` использует объекты, созданные конструктором по умолчанию для проверки шаблонного хранения и копирования, а геометрические расчёты выполняются с `double`.

## Готовый пример работы

Ввод для равностороннего треугольника:

```text
add 3
0 0
2 0
1 1.7320508075688772
list
total
exit
```

Фрагмент фактического вывода интерактивной части:

```text

> [0] Triangle
  Вершины: (0, 0) (2, 0) (1, 1.732050808)
  Центр: (1, 0.5773502692)
  Площадь: 1.732050808

>
```

В проверенном сценарии также добавлялись правильные шестиугольник и восьмиугольник. Общая площадь трёх фигур составила `14.95278278`; после `remove 1` остались треугольник и восьмиугольник с общей площадью `4.560477932`. Команда `remove 9` вывела `Array index is out of range`, не изменив массив.

## Ход выполнения работы

1. **Проектирование `Scalar` и `Point<T>`.** Ограничение `Scalar` определено через `std::is_scalar_v<T>` и указано в шаблонах точек и фигур. `Point<T>` содержит публичные координаты `x`, `y` и автоматически сгенерированное сравнение. Проверки `static_assert` подтверждают допустимость `int` и `double` и отклонение нескалярного типа.
2. **Проектирование `Figure<T>`.** Абстрактный интерфейс включает центр, площадь через `explicit operator double`, потоковые операции, сравнение, тип, `clone` и виртуальный деструктор. Центр всегда возвращается как `Point<double>`, поэтому дробная часть не теряется даже при целочисленных координатах.
3. **Хранение вершин.** Общий код правильных многоугольников вынесен в `RegularPolygon<T, N>`. Каждая вершина принадлежит отдельному `std::unique_ptr<Point<T>>`, а массив указателей имеет фиксированный размер `N`. Наследники задают только имя типа и реализацию `clone`.
4. **Проверка и вычисления.** Площадь вычисляется по формуле площади многоугольника через координаты. Перед принятием координат проверяются ненулевая площадь, одинаковая ориентация всех смежных троек вершин, равенство сторон и равенство диагоналей через одну вершину. Центр вычисляется как среднее координат правильной фигуры.
5. **Глубокое копирование и перемещение.** Копирующий конструктор выделяет новые `Point<T>` для каждой вершины. Копирующее присваивание сначала создаёт независимый набор точек и затем обменивает его с текущим. Перемещение передаёт владение `unique_ptr` без копирования точек. Сравнение учитывает динамический тип и значения координат.
6. **Реализация `Array<T>`.** Хранилище представлено `std::shared_ptr<T[]>`, дополнительно хранятся размер и ёмкость. Реализованы два варианта `push_back`, удаление со сдвигом, проверяемый `operator[]`, конструкторы и присваивания копирования/перемещения. Копия массива владеет отдельным хранилищем.
7. **Расширение без копирования элементов.** При заполнении ёмкости создаётся новый `std::shared_ptr<T[]>` удвоенного размера. Существующие элементы переносятся выражением `newData[i] = std::move(data_[i])`. Тест `MoveProbe` подтверждает нулевое число копирований и наличие перемещающих присваиваний при расширении.
8. **Демонстрации.** Интерактивная программа хранит `shared_ptr<Figure<double>>` и вызывает виртуальные функции через базовый тип. Отдельный код создаёт `Array<std::shared_ptr<Figure<int>>>` и `Array<Hexagon<int>>`, включая копирование конкретных объектов и клонирование через базовый интерфейс.
9. **Тестирование.** GoogleTest подключён через `FetchContent`, каждый тест зарегистрирован в CTest. Проверены вычисления, ввод/вывод, ограничения, копии, перемещения, сравнение, клонирование, полиморфизм, массивы, ошибки индексов и некорректные координаты.
10. **Вывод.** Шаблоны и concepts позволили использовать один безопасный код для разных скалярных типов. Умные указатели сделали владение явным, а явное глубокое копирование исключило разделение вершин между независимыми фигурами. Перемещение при расширении массива устранило лишние копии.

```bash

git push -u origin main
```

Заменить `USERNAME/REPOSITORY` на фактические значения. Перед отправкой повторно выполнить сборку и CTest из чистого каталога. Текущая подготовка проекта не включает автоматический `commit` или `push`.
